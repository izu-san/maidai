# MaidAI リポジトリ概要と梨乃の使い方

最終更新: 2026-09-29  
対象: このリポジトリの現行コード・設定

## これは何か

MaidAI は、ローカル PC 上で動く「梨乃」という会話 AI を中心に、会話、音声、画像生成、スマート家電、生活記録、PC 状態監視をつなぐためのプロジェクトです。

梨乃は単に雑談するキャラクターではなく、必要に応じて専用のエージェントサービスへ依頼を渡し、許可された外部機能を安全に使えるように設計されています。すべての会話を自動的に家電操作へ変換するのではなく、家電操作などの依頼時だけエージェントを使う想定です。

## 現在の構成

```text
利用者
  └─ SillyTavern（梨乃との会話 UI）
       ├─ KoboldCpp → Gemma 4（ローカル LLM）
       └─ 日本語の家電・生活依頼（または /rino <依頼>）→ Rino Agent Service
                              ├─ ポリシー・承認・監査
                              ├─ SwitchBot MCP（現在有効）
                              ├─ Rino Life MCP（現在有効）
                              └─ OBS / ComfyUI / Windows MCP（既定では無効）

生活イベント・PC監視・SwitchBot観測
  └─ Rino Life（PostgreSQL + NATS JetStream）
       ├─ 消耗品・通知履歴・状態の保存
       └─ 通知候補の判定
```

「MCP」は、梨乃が外部の機器やアプリを扱うための接続規格です。梨乃は機器の認証情報を直接会話に出さず、専用 MCP を経由して決められた操作だけを行います。

## 技術スタック

| 領域 | 採用技術 | 役割 |
|---|---|---|
| 会話 UI | SillyTavern | 梨乃とのテキスト会話、対応する自然文によるエージェント依頼（`/rino` も利用可） |
| ローカル LLM | KoboldCpp + Gemma 4 | 会話文の生成、ツール呼び出しの判断。OpenAI 互換 API として利用 |
| エージェント実行 | Microsoft Agent Framework、Python | 会話セッション、ツール呼び出し、承認待ち、ワークフロー |
| API | FastAPI + Uvicorn | Rino Agent Service と Rino Life のローカル HTTP / WebSocket API |
| 外部ツール連携 | MCP (Model Context Protocol) | SwitchBot、将来の OBS・ComfyUI・Windows 操作の境界 |
| 家電連携 | SwitchBot OpenAPI | 室内環境の取得、照明・エアコン・テレビ・玄関ロック操作 |
| 生活データ | PostgreSQL 16 + SQLAlchemy + Alembic | 消耗品、イベント、通知履歴、各種状態の永続化 |
| イベント配信 | NATS JetStream、TypeScript の Event Bus | 観測イベントを耐久的に配信し、各処理へ渡す |
| 設定・検証 | YAML、JSON Schema、Pydantic、pytest | 設定、イベント形式の検証、テスト |
| 音声 | Edge TTS、RVC、GPT-SoVITS（個別運用） | 読み上げ・声質変換。起動対象はプロファイルにより異なる |
| 画像 | ComfyUI 連携用実装、SillyTavern Extras | 画像生成。Agent API は環境変数で明示的に有効化した場合のみ利用可能 |
| インフラ | Docker Compose | Rino Life 用 PostgreSQL / NATS、既存の MemPalace / SearXNG の起動補助 |

基本的に外部公開を前提にしておらず、Rino Agent Service は `127.0.0.1:8766`、Rino Life API は標準で `127.0.0.1:54330` にバインドします。Agent API は `GET /health` 以外で Bearer トークンを要求します。

## 起動の入口

プロジェクト直下で以下を実行します。

```powershell
.\Start-MaidAI.ps1            # 会話用（Docker 基盤、Gemma 4、SillyTavern、Agent）
.\Start-MaidAI.ps1 -Profile voice  # RVC API + Edge TTS
.\Start-MaidAI.ps1 -Profile full   # 会話・Agent・音声系
.\Start-MaidAI.ps1 -Profile docker # Docker 基盤のみ
.\Start-MaidAI.ps1 -Status         # 稼働状態の確認
```

`chat` と `full` では Rino Life の PostgreSQL / NATS を Docker Compose で healthcheck 完了まで起動し、DB migration、消耗品 seed、JetStream 初期化を済ませてから Life API と Agent を起動します。初回に Agent を使う前は `Initialize-RinoAgent.ps1` でローカル API トークンを作成します。詳細は [起動ハブの使い方](起動ハブの使い方.md) と [Rino Agent Phase 0 Runbook](../operations/Rino_Agent_Phase0_Runbook.md) を参照してください。

## 梨乃に自然言語で頼めること（現在有効）

SillyTavern の入力欄から、普段どおり日本語で依頼できます。家電操作・生活記録に該当する明示的な依頼は Agent へ送られ、それ以外の雑談は通常の梨乃との会話として扱われます。`/rino` に続ける書き方も、明示的に Agent へ依頼したい場合に利用できます。梨乃が実際の操作を行うのは、SwitchBot の接続情報・対象デバイスが設定され、Agent Service が起動している場合です。

| 目的 | 指示例 | 扱い |
|---|---|---|
| 室内の確認 | `今の部屋の温度、湿度、CO2を教えて` | そのまま実行 |
| 照明 | `電気を消して` / `電気をつけて` | そのまま実行 |
| エアコン電源 | `エアコンをつけて` / `消して` | そのまま実行 |
| エアコン温度 | `エアコンを26度にして` | 毎回、内容確認後に承認が必要。設定可能範囲は 16〜30℃ |
| テレビ | `テレビを消して` | そのまま実行 |
| テレビ電源オン | `テレビをつけて` | 毎回承認が必要 |
| 玄関の確認 | `玄関は閉まってる？ 鍵は？` | そのまま実行 |
| 施錠 | `玄関に鍵をかけて` | 毎回承認が必要 |
| 就寝準備 | `寝る準備をして` | テレビをオフにしてから照明をオフにする定型処理。玄関施錠は含まない |

玄関の**解錠**機能は意図的に提供していません。また、操作後に SwitchBot から状態を再取得できない場合、梨乃は「完了」と断定せず、「コマンドは送信したが確認できなかった」と報告する設計です。

### 承認が必要なとき

温度変更、テレビをつける、施錠などでは、梨乃が対象操作・引数・リスクを示して確認を求めます。その会話セッション内で `はい`、`お願い`、`yes`、`ok` などと明確に返すと承認されます。`いいえ`、`不要`、`cancel` は拒否です。

承認は 60 秒で失効し、一度だけ使えます。セッションを取り消すと、そのセッションの保留中承認も無効になります。サービス再起動後に、保留中の危険な操作が自動再開されることもありません。

## 梨乃から受け取れる通知

通知には「今すぐ会話画面へ確実に届くもの」と「基盤側で検知・記録できるもの」があります。現状の接続範囲を分けて理解することが重要です。

### Agent Service のイベント待機通知（利用可能）

指定したローカルイベントを待ち、受信時に完了通知を WebSocket / SillyTavern 側へ送る仕組みがあります。イベントをきっかけに外部操作を勝手に再開することはありません。

想定例:

- 「ComfyUI の生成が終わったら教えて」
- 「OBS の録画が終わったら知らせて」
- 「ゲームの周回完了を検知したら通知して」

実際に通知されるには、それぞれの Vision、ComfyUI、OBS などが `rino-agent-event` 相当のローカルイベントを送る連携を別途設定する必要があります。待機の有効期限は 1 秒〜24 時間です。

### Rino Life の生活・PC 通知（基盤は実装済み）

Rino Life は生活イベントを PostgreSQL に保存し、NATS 経由で通知候補を判定します。現在の設定では洗濯洗剤と柔軟剤が登録されています。

| 検知内容 | 例 | 現在の扱い |
|---|---|---|
| 消耗品の残量低下 | 「洗濯洗剤が 150 ml 以下」 | 通知候補を記録・ルーティング |
| ディスク空き容量不足 | 空き容量が既定の 20 GiB 未満 | 2 回連続検知でイベント化 |
| CPU / メモリ高負荷 | 使用率が既定の 90% 以上 | 2 回連続検知でイベント化 |
| PC ハードウェア異常・サービス異常 | 監視側からの異常イベント | 高優先度の候補として扱う |
| SwitchBot 観測値 | 温度、湿度、CO2、玄関の鍵・ドアの状態 | 5 分間隔で読み取り専用に取得し、最新値・履歴を保存。基準を外れたらチャットへ通知 |

通知候補は、低確信度、夜間（23:00〜7:00）、重複、クールダウン、未解決の同一通知を考慮して抑制・集約されます。ハードウェア異常は夜間抑制の対象外です。

**消耗品の残量低下、SwitchBot の室内環境・玄関の警告、PC の警告（ディスク空き容量の不足・CPU / メモリ使用率の高止まり・重要な Windows サービスの停止・ハードウェア関連のシステムログエラー）は、判定で「送る」となったとき、梨乃のチャット欄にメッセージとして届きます。** PC の監視は Life API の起動と同時に自動で始まります（60 秒間隔。ディスク・CPU・メモリ・サービスは 2 回連続で基準を外れたときだけ検知）。サービス監視の対象は既定で `EventLog` / `Winmgmt` / `Dnscache` / `Dhcp` / `LanmanWorkstation` で、環境変数 `RINO_PC_WATCH_SERVICES`（カンマ区切り）で変更できます。ハードウェアエラーは Windows のシステムログ（disk / Ntfs / volmgr / stornvme / storahci / WHEA-Logger / GPU ドライバ）の Critical・Error を、監視開始後に増えた分だけ通知し、静音時間帯でも届きます。CPU / メモリは静音時間帯（23:00〜7:00）には送られません。

SwitchBot の観測も Life API の起動と同時に自動で始まります（既定 5 分間隔、`RINO_SWITCHBOT_POLL_SECONDS` で変更可、下限 60 秒。読み取りのみでコマンドは送りません）。通知の基準は次のとおりです。CO2 が 1100 ppm 以上、湿度が 30% 以下または 70% 以上のときは換気・加湿などを促すメッセージが届きますが、静音時間帯には送られません。温度が 29℃ 以上または 10℃ 以下、玄関の鍵が解錠のまま 30 分以上、ドアが開いたまま 30 分以上、鍵のジャムは、静音時間帯でも届きます。基準内に戻ると解決済みになり、同じ種類の通知は 12 時間空けて再度届きます。玄関の鍵の状態は、取得できない場合は判定しません。 通知は Agent Service の受信箱に入り、SillyTavern が梨乃とのチャットを開いている間に 15 秒間隔で取得して表示します。閉じていた間の分は、次に開いたときにまとめて表示されます（Agent Service を再起動すると未表示の分は消え、24 時間を過ぎた分も破棄されます）。表示するだけで、Agent の操作は実行しません。通知はチャット上の通常の梨乃の発言として追加されるため、読み上げは SillyTavern の TTS 設定（自動再生など）に従います（Life 側に音声用の配送はなく、実際に読み上げられるかは未確認です）。上表の通知は、いずれも梨乃のチャット欄へ届く内容です。

## 生活管理に記録できること

Rino Life の MCP は Agent に接続済みです。Rino Life API と DB 基盤を起動・初期化した環境では、自然文で次の記録・確認を依頼できます。`/rino` を付けても利用できます。記録は Life API のイベント書き込み境界を経由し、Outbox / NATS の配信経路を維持します。

| 発言・意図の例 | 記録される内容 |
|---|---|
| 「洗濯終わった」「今日 2 回洗濯した」 | `laundry.completed`。設定量に従い洗剤・柔軟剤を減算 |
| 「洗剤を 2 本買った」 | 未開封ストックを加算 |
| 「新しい洗剤を開けた」 | 未開封ストックを減らし、使用中の残量を更新 |
| 「洗剤は 300 ml くらい残ってる」 | 推定値として残量を手動補正 |
| 「この洗剤を管理に追加して」 | 必要な項目を会話で確認してから登録 |

### 消耗品を会話で追加する例

最初の一文で登録情報をすべて伝える必要はありません。梨乃は、登録に必須の品名、カテゴリ、単位、1 容器あたりの容量を確認し、任意で現在の残量、未開封数、消費量の計算方法（毎日一定量・洗濯ごと・手動のみ）、残量通知の閾値を確認します。

> あなた: 猫の餌を管理対象に追加して  
> 梨乃: かしこまりました。単位と一袋あたりの容量を教えてください。現在開封している分の残量や、未開封の袋数も登録しますか？  
> あなた: ドライフード、2 kg 袋。今は 800 g 残っていて、未開封が 1 袋。300 g で知らせて。毎日 50 g 食べるよ。  
> 梨乃: 猫のドライフードを管理対象に登録しますね。容量は2,000g（2kg）で、今の残量は800gです。未開封のストックは1個です。毎日50gずつ自動で減らします（登録した翌日から）。残りが500g以下になったらお知らせします。この内容でよろしいですか？（はい／いいえ）

「毎日一定量」を指定した消耗品は、登録した当日を起点に、翌日以降 1 日ごとに指定量を自動で減算します（日本時間の日付基準）。Life API が停止していた日数分は、次回起動時にまとめて反映され、減算後の残量は推定値として扱われます。洗濯洗剤・柔軟剤は「洗濯した」と伝えたときだけ減算します。減算方法を指定しない品目は、残量を伝えたとき・開封・購入時のみ更新されます。

登録内容を確認した後、梨乃は上のように単位付きの自然な文で承認を求めます。容量が 1000 g 以上のときは kg も併記されるので、単位の取り違え（2 kg を 2 g など）に気づけます。「はい」「いいよ」「大丈夫」などで承認、「いいえ」「やめて」などで拒否できます。承認待ちの間に別の言葉を送ると、「承認待ちです」と返します。容量・通知の閾値・毎日の減算量が単位と矛盾する登録（例: g で容量 10 未満）は、実行時に拒否されます。承認されると、登録イベントが Life API を経由して保存され、履歴と通知判定の対象になります。残量が閾値以下になると、通知判定（重複・12 時間のクールダウン・23:00〜7:00 の静音）を通ったものが梨乃のチャット欄に表示されます。読み上げは SillyTavern の TTS 設定に依存します（Life 側に音声用の配送はありません）。

新しい消耗品の登録・管理対象からの削除は内容確認後の承認が必要です。洗剤・柔軟剤の現在の初期設定、Life API の起動方法、通知ルーターの詳細は [Rino Life README](../../rino_life/README.md) を参照してください。PC の警告もチャット欄に届きます。

## 家計簿に記録・確認できること

Rino Life の基盤を起動している場合、梨乃に会話で家計簿を頼めます。日本円の手入力だけを扱い、口座残高、クレジットカード・銀行連携、CSV 取込、予算、資産管理、外貨換算は扱いません。

| 発言・意図の例 | 扱い |
|---|---|
| 「コンビニで650円使った」 | 食費の支出候補として金額・カテゴリ・日付を確認してから記録 |
| 「今日の交通費を500円で記録して」 | 内容確認後に交通費の支出として記録 |
| 「今月の家計簿を見せて」 | 収入、支出、差額、カテゴリ別内訳を表示 |
| 「今月の明細を出して」 | 月内の記録済み取引を表示 |
| 「さっきの650円を750円に直して」 | 対象取引を確認後、履歴を残して訂正 |
| 「その支出を取り消して」 | 対象取引を確認後、履歴を残して取消 |

支出・収入の記録、訂正、取消は、金額・カテゴリ・日付・メモを要約してから毎回承認を求めます。日付を指定しなければ日本時間の当日を使います。訂正や取消は元の記録を消さず、監査可能な履歴として残ります。

## 実装済みだが既定では使えない指示

OBS、ComfyUI、Windows 用 MCP はコードとポリシーを持ちますが、`rino_agent/config/mcp.yaml` で `enabled: false` です。したがって、次のような依頼は、接続先と許可リストを設定して有効化するまで実行されません。

| 連携先 | 将来可能になる依頼例 | 制限 |
|---|---|---|
| OBS | 「録画を始めて」「配信を止めて」「シーンをゲームに切り替えて」 | OBS WebSocket 経由。配信・録画の開始停止は承認対象 |
| ComfyUI | 「ワークフロー一覧を見せて」「このプロンプトで生成して」「生成を止めて」 | ローカル HTTP と指定ワークフローディレクトリに限定。投入・取消は承認対象 |
| Windows | 「音量を下げて」「許可済みの OBS を起動して」「スクリーンショットを撮って」 | 事前許可アプリ・フォルダーのみ。任意のシェル、PowerShell、レジストリ、マウス・キーボード操作は不可 |

画像生成 API も `RINO_IMAGE_GENERATION_ENABLED=true` を明示した場合だけ有効です。機能を有効化する際は、[Rino MCP Operations](../operations/Rino_MCP_Operations.md) とポリシー設定を確認してください。

## 安全のためのルール

- 外部操作の直前に、ツール名・引数・モード・依頼元に基づくポリシー判定を行います。
- 操作、承認、イベント、結果は秘密情報を伏せて監査ログへ残します。
- MCP サーバーは Agent Service が所有するローカル標準入出力プロセスで、HTTP 公開しません。
- SwitchBot のトークンやデバイス ID は LLM の会話コンテキストへ返しません。
- Windows 連携を有効化しても、任意コマンドを実行できる万能シェルは提供しません。
- Vision 由来の観測は「確認が必要な候補」として扱い、単独で家電操作や生活状態の確定を起こしません。
