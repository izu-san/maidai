# MaidAI 起動ハブ

プロジェクト直下で、次のいずれかを実行します。

```powershell
.\Start-MaidAI.ps1                  # 会話: Docker基盤→Gemma 4→SillyTavern→Life API→Agent
.\Start-MaidAI.ps1 -Profile voice   # RVC API + EdgeTTS のみ
.\Start-MaidAI.ps1 -Profile full    # 会話、Life、音声系をまとめて起動
.\Start-MaidAI.ps1 -Profile docker  # Rino Life の PostgreSQL / NATS と既存Dockerコンテナのみ
.\Start-MaidAI.ps1 -Status          # 起動状態を確認
.\Start-MaidAI.ps1 -Stop            # ポートが判別できるサービスを停止
.\Start-MaidAI.ps1 -Status -Json    # 状態を JSON で出力（name / kind / port / state / pid / process）
.\Start-MaidAI.ps1 -Component 'SillyTavern' -Action restart   # 個別に start / stop / restart
```

`-Component` に指定できるのは `-Status -Json` に現れる名前（ローカルサービス、Docker コンテナ、`Rino Life` Compose プロジェクト）だけです。未知の名前はエラーになり、任意コマンドは実行されません。`state` は `running` / `loading` / `stopped` / `missing` / `unavailable` のいずれかです。

## デスクトップウィジェット

```powershell
py -3.13 -m pip install -r requirements-rino-launcher.txt   # 初回のみ（PySide6）
.\Start-MaidAIWidget.cmd
```

常時最前面の小型ウィジェットが `-Status -Json` を 5 秒ごとに取得し、各サービスの状態ランプ（緑=起動中、黄=読込中、灰=停止）と 起動 / 停止 / 再起動 ボタンを表示します。起動中・読込中の行には起動からの経過時間（例: `3時間5分`）を併記し、行にマウスを載せると最終起動時刻（ローカル時刻）がツールチップに出ます。Docker コンテナは停止中でも直近の起動時刻を表示し、Compose プロジェクトはメンバーのうち最新の起動時刻を使います。状態・経過時間・ポートは固定幅の列で揃えて表示します（ポートのない Compose プロジェクトは空欄）。ウィジェットの位置は移動のたびに記録され（Windows のレジストリ `HKCU\Software\MaidAI\Launcher`）、次回起動時に同じ位置へ復元されます。保存位置が現在のどのモニターにも収まらない場合は既定位置で起動します。時刻は `-Status -Json` の `started_at`（UTC の ISO 8601、不明は `null`）から得ます。上部の `chat` / `voice` / `full` / `docker` は各プロファイルの一括起動、「全停止」は確認後に `-Stop` を実行します。タスクトレイのアイコンからも同じ操作ができ、`－` でトレイへ格納できます。ウィジェットは `Start-MaidAI.ps1` を呼び出すだけで、サービス定義や秘密情報は持たず、ネットワーク公開もしません。

ウィジェットの追加機能:

| 機能 | 内容 |
|---|---|
| ブラウザで開く | SillyTavern の行の `↗` で `http://127.0.0.1:8000/` を既定ブラウザで開く（loopback の URL のみ） |
| 応答異常の表示 | 稼働中でも応答確認に失敗すると橙色の「応答異常」になる。確認は KoboldCpp（`/api/v1/model`）、SillyTavern、Rino Agent Service / Rino Life API（`/health`）は HTTP、Docker は healthcheck 定義があるコンテナのみ。確認手段のないサービスは判定しない |
| 異常通知 | 起動中だったサービスが停止した、または応答しなくなったとき、トレイのバルーンで知らせる。ウィジェット自身の操作中と、その完了後 10 秒間は通知しない（意図した停止と区別するため） |
| ログを開く | 各行の `☰` でそのサービスのログを開く。サービスの標準出力・標準エラーは、起動ハブが起動した分から `logs\services\<名前>.log` に追記される（5MB 超で `.old.log` へ退避。KoboldCpp は標準エラーを `<名前>.err.log` に分ける）。Docker はその時点の `docker logs` 末尾を書き出して開く。起動ハブ経由でまだ起動していないサービスのログはない。`logs/` は git 管理外 |
| 自動起動 | フッターの「自動起動」で、Windows ログイン時のウィジェット起動を切り替える（`HKCU\Software\Microsoft\Windows\CurrentVersion\Run` の `MaidAIWidget`。管理者権限は不要） |
| VRAM 表示 | `nvidia-smi` が使える環境で、先頭 GPU の VRAM 使用量と使用率を表示する。使えない環境では表示しない |
| プロファイルの充足 | `chat` / `voice` / `full` / `docker` ボタンの色で、そのプロファイルの構成要素が全て稼働（緑）／一部のみ（黄）／未起動（既定色）を示す。構成は `Start-MaidAI.ps1` の `$ProfileComponents` が唯一の定義 |

`-Status -Json` の各要素には、`started_at` に加えて `health`（`ok` / `fail` / `null`）、`open_url`、`profiles`（そのコンポーネントを起動するプロファイル名）が含まれます。`-Component <名前> -Action log` はログファイルのパスを最終行に出力します。

`chat` が既定です。まず Rino Life の Compose 基盤が healthcheck を通るまで待機し、DB migration、消耗品初期データ、JetStream stream / consumer を冪等に初期化します。その後、Gemma 4（KoboldCpp）、SillyTavern、Rino Life API、Rino Agent Service の順に、各ポート応答を待って起動します。初期化に必要な Python 依存関係または Docker が不足する場合は、Agent を起動せずエラーで停止します。

## Docker を使うサービス

`Start-MaidAI.ps1` は `infra/compose.life.yaml` の Rino Life Compose プロジェクト（PostgreSQL / NATS JetStream）を登録済みです。`chat`、`full`、`docker` では `docker compose up -d --wait` で両サービスの healthcheck 完了を確認します。PostgreSQL は `127.0.0.1:54329`、NATS は `127.0.0.1:54222`、NATS 監視 API は `127.0.0.1:58222` にのみ公開されます。

既存コンテナの `mempalace` と `searxng` も同じプロファイルで起動します。`full` は Compose 基盤と Life 初期化の後、Gemma 4 → SillyTavern → Rino Life API → Rino Agent Service → RVC API → EdgeTTS の順で起動します。

Rino Life API の起動中は outbox publisher、通知 router、SwitchBot / PC / Vision の状態 consumer も同じローカル Python プロセスで稼働します。通知 router は消耗品の残量低下、SwitchBot の警告、PC の警告（ディスク空き容量・CPU・メモリ）を Agent Service の受信箱へ渡し、梨乃のチャット欄に表示されます（Life API 側は `RINO_AGENT_API_TOKEN` と任意の `RINO_AGENT_URL`（loopback のみ）を使用）。音声読み上げは Life 側では扱わず、SillyTavern の TTS 設定に依存します。Life の worker が Agent 操作を起動することはありません。SwitchBot の観測 producer（室内の温度・湿度・CO2 と玄関の鍵・ドアの状態を読み取り専用で 5 分間隔に取得。`RINO_SWITCHBOT_POLL_SECONDS` で変更可、下限 60 秒。SwitchBot の認証情報とデバイス ID が未設定の項目は取得しません）と、PC の監視 producer（ディスク・CPU・メモリ・サービス停止・システムログのハードウェアエラー）も同じ Life API プロセスで自動的に動き、別途起動する必要はありません。任意の環境変数として `RINO_PC_MONITOR_PATH`（空き容量を見るパス。既定はシステムドライブ）と `RINO_PC_WATCH_SERVICES`（監視する Windows サービス名のカンマ区切り。既定は `EventLog,Winmgmt,Dnscache,Dhcp,LanmanWorkstation`）を使えます。

```powershell
@{ Name = '検索エンジン'; Path = 'D:\AI\検索エンジン\compose.yaml'; Services = @() }
```

`-Stop` は、ポートで判別できるネイティブサービスに加え、登録済みの Docker コンテナと Compose サービスを停止します。Compose サービスには `docker compose stop` を使うため、コンテナ、ネットワーク、PostgreSQL / NATS の永続ボリュームは削除しません。次回の起動では既存コンテナを再開します。

GPT-SoVITS は起動ハブの管理対象外です。必要になった場合は、専用の手順で個別に起動してください。
